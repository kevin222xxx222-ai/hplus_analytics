# Management Dashboard Design Principles

- スクロールだけで当月・全店舗の状態を理解できる
- プルダウンで対象を切り替えず、全店舗を同時表示する
- 目標・必要値・着地予測は置かず、HOMEと責務を分ける
- 実績と比較結果を表示し、因果関係を断定しない
- 欠測・対象外・未取得・0を区別する
- HOMEと同じHeader、Card、Spacing、Typography、Semantic Color、DATA HEALTH、導線を使用する
- 詳細な店舗・Trend・Time・Cast分析は専門ページへ委譲する

## 日次グラフの判断フロー

数字を見る
↓
変化や異常を見つける
↓
Trend / Store / Castへ進む

- グラフは実績観察のために使う
- 単位の異なる指標を同一軸に混ぜない
- 欠測を線でつながない
- 店舗色とSemantic Colorを分離する
- スクロールだけで全体を理解できるようにする
# Phase F-1D Story Design Principles

- 単独KPIの羅列より、活動 → 閲覧 → 成約 → 売上の同日軸の関係性を優先する。
- 全体と店舗の系列を1グラフへ重ねず、縦のScope Blockで観察する。
- 縦に長くなっても、店舗名・指標順・説明が明確であることを優先する。
- 同時変化は観察結果であり、媒体が売上を生んだ等の因果関係を断定しない。
- 母集団の異なる指標を安易に比較しない。Townは春日部＋越谷、Heavenは春日部のみを正式範囲とする。
- 欠測を0で補完せず、対象外のScopeはカード・系列を生成しない。
- 売上を共通基準として関係性を観察し、1カード1Scope、売上はBar・比較指標はLineとする。
- 方向一致率は相関係数ではなく、軸の目盛りを恣意的に調整して変化を誇張しない。
- 店舗色ではなく指標色を使い、凡例と左右軸ラベルを必ず併記する。
- 売上／時間は勤務時間の店舗帰属制約によりManagement Dashboardの主要表示から外す。平均単価とMITENE_SENTも主要Storyには含めない。
# Dashboard v2 UI principles

- 関係性をカード単位で分断せず、1枚のStory Card内で読む。
- カード数より理解の速さを優先し、説明・欠測表示・凡例を繰り返さない。
- 全体＋3店舗のStoryは2×2、Townは最大3カラム、Heavenは春日部の全幅1カードとする。
- 公式値と参考値を区別し、推定値を正式値として表示しない。
- 同方向の一致率は前日差の観察値であり、統計的相関や因果を意味しない。
- Story Card内で売上／時間、平均単価、MITENE、オキニトークを主要表示しない。
- 店舗を平等に扱うより、データ信頼性を優先する。
- 信頼できない店舗別指標は「参考値」として大量表示せず、主要分析から非表示にする。
- 横スクロールを主要UIに使用せず、縦に長くても全情報を読める構成にする。
- 春日部を主要分析対象、越谷を売上・Town中心、野田を売上推移中心とする。
- MITENE・OKINIは活動指標として扱い、店舗売上と安易に結び付けない。
- TownとHeavenを比較する場合は同一店舗Scopeに限定する。

## F-2C Final Polish

- 店舗状態と店舗実績は「店舗概要」1カードへ統合する。
- 上昇・低下・横ばいは必ず「前月同期間比」を基準として明示する。
- 前月比較は当月と同じ経過日数の期間を使用し、前月全月とは比較しない。
- 媒体横断はTown PVとHeaven PAGE_ACCESSの絶対値を表示し、指数化・正規化しない。
- 同じグラフを複数Storyへ重複表示しない。未接続メトリクスの空グラフも生成しない。
- 横スクロールを主要UIに使わず、幅不足時はカードを縦積みにする。
