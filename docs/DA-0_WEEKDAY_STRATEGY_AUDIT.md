# DA-0 曜日×週×顧客構成 監査

監査CLIは次で実行する。

```bash
npm run audit:weekday-strategy -- --from=2026-04-01 --pretty
```

出力は `artifacts/audits/weekday-strategy/` にJSONとMarkdownで生成する。対象は全体（春日部・越谷の合算）、春日部、越谷。野田は店舗分析対象外として集計せず、混入行だけ監査する。

曜日別の主役値は売上・女子報酬・成約・新規・リピート・本指名・出勤・稼働・Town値の絶対値とし、相対差率は補助値に留める。行のない日・媒体値の欠測は0に補完しない。Heavenは春日部だけをVALUE／ZERO／MISSINGで扱い、越谷・野田はUNAVAILABLEとする。

第何週は、月内日付による案Aを第一候補、月曜始まりの暦週による案Bを補助軸として両方出力する。祝日は曜日を失わず`isHoliday`で分離し、祝日と通常日のサンプル数を別に確認する。月途中の月はPARTIAL、月末まで確定した月はCOMPLETEとする。

曜日分析は「弱い曜日を自動で断定する」機能ではなく、絶対値・顧客構成・出勤・週セルのサンプル数・Availabilityを同時に見て、営業施策候補を検討するための基盤とする。因果やキャスト個人の良し悪しはこの監査では断定しない。

## 第何週・サンプル監査

案A（月内日付）は第1週5日、第2〜4週4日、第5週は多くのセルが1〜2日で、営業施策の月初・月末と対応しやすい。案B（月曜始まり暦週）もJSONに出力したが、月境界で週が分断されるため主軸には案Aを推奨する。第5週の1〜2サンプルは傾向判定に使わない。全体の案A売上例は第1週の月〜日が2,613,000／2,218,000／2,056,000／2,307,000／2,383,000／1,805,000／1,845,800円、第4週は1,823,000／2,013,000／1,700,000／2,023,500／1,771,000／2,310,500／1,676,000円。

Heavenは春日部のみでVALUE 67日、MISSING 62日、越谷は全129日UNAVAILABLE。越谷へ0補完しない。出勤人数と売上の記述相関は全体r=0.08（n=129）で一様な増員効果は確認できず、越谷はr=0.42（n=129）。Town UUと売上は全体r=0.43（媒体値が揃うn=68）だが、いずれも因果ではない。給与日仮説の窓別平均売上は1〜5日436,080円、10〜20日471,480円、21〜24日443,469円、25〜27日474,042円、28日以降487,500円で、制度要因を断定できる差ではない。

## 要件・実装判断

正式UIの優先5情報は、(1)曜日別絶対売上・サンプル、(2)新規／リピート／本指名の絶対値、(3)出勤人数・稼働時間、(4)曜日×案A週セルとセルサンプル、(5)Town／HeavenのAvailability付き媒体値。グラフ優先度は、A曜日別売上Bar、B新規／リピートBar、C曜日×週Heatmap、E成約数、D出勤×売上Scatterの順。Scatterはサンプルと店舗規模を併記する。比較画面は2〜3曜日を絶対値カードで比較する設計が成立する。

推移分析へ渡すキーは`storeId`、`weekday`、`weekOfMonth`（案A）、`month`、`metric`、`sampleDays`、`isHoliday`。曜日分析は「どこを強くすべきか」、推移分析は「施策後にどう変化したか」と分離できる。DA-1へ進行可能だが、HeavenのMISSING日、越谷UNAVAILABLE、5週セルの少数サンプルをUIで明示することが前提である。
# DA-2.2 表示原則追記

曜日分析の通常表示は、売上・成約・顧客構成・供給・媒体の絶対値を主役とする。順位、スコア、○△◎、Diagnosis、Priorityは表示しない。

曜日×第何週ヒートマップだけは、35セル内の分布を発見しやすくする補助表現として相対色を使う。累計表示でも色の判定値は「累計 ÷ 有効対象日数」の1日平均で正規化し、第5週など対象日数が少ないセルを日数だけで不利にしない。表示値と対象日数は常に併記する。

色は低い値を赤系、中間を白、高い値を緑系とするが、赤は「悪い／要改善」、緑は「良い」を意味しない。色は同一指標の曜日×週の差異を見つけるためだけに用い、営業施策Ruleや自動判定へ接続しない。

実装上の色分けは、35セルの有効な1日平均値を昇順に並べ、下位25%・上位25%を淡い赤／緑、それ以外を白とする四分位（quantile bucket）方式とした。極端な1セルのmin/maxだけで全体の色差が消えないようにするためである。
